# 听力练习工具 Constitution

## Core Principles

### I. 本地优先（NON-NEGOTIABLE）
本工具完全在本地运行。核心功能（音频播放、复读、变速、听写练习、进度记录）不得
依赖网络连接或远程服务。用户的音频文件、听写文本与练习记录必须存储在本机，禁止
上传至任何第三方服务。可选的在线能力必须可关闭，且关闭后核心功能不受影响。
理由：练习数据属于用户隐私；离线可用保证用户在任何网络环境下都能练习。

### II. 开箱即用
用户获取工具后无需编译、无需配置即可开始第一次听力练习：启动时提供合理默认值，
零必填配置项。若需要用户提供内容（如音频或字幕文件），必须明确提示支持的格式
并引导选择。从首次启动到开始练习的操作不得超过三步。

### III. 核心逻辑可测试（NON-NEGOTIABLE）
播放控制、复读区间、变速、听写比对等核心逻辑必须与 UI 解耦，关键路径必须有单元
测试覆盖。新增或修改核心逻辑遵循先写失败测试再实现的顺序（Red-Green-Refactor）。
理由：听力练习依赖精确的时间控制与文本比对，回归缺陷直接破坏练习体验。

### IV. 流畅体验与进度可恢复
练习中断（关闭应用、系统休眠）后重新打开时，必须恢复到上次的音频位置与练习进度。
播放、暂停、复读、变速操作不得出现可感知的卡顿；长音频加载不得阻塞界面。
进度状态变更时必须立即持久化，不得依赖正常退出流程。

### V. 简洁与单一职责（YAGNI）
工具只做听力练习：播放、复读、变速、听写/对照、进度记录。不加入社交、内容推荐、
账号体系等与核心目标无关的功能。每个新功能在进入开发前必须在规范中说明它如何
服务于听力练习这一目标；无法说清的一律不做。

## Technology Constraints

- 技术栈以项目现有选择为准；新增依赖须证明无法用标准库或现有依赖实现，
  禁止引入重量级框架。
- 优先支持 Windows；跨平台能力在需求明确后再考虑，不为假想中的平台预做抽象。
- 音频与字幕使用开放标准格式（如 MP3/WAV、SRT/TXT/LRC）；用户数据以可读格式
  （JSON 或纯文本）存储，禁止用私有二进制格式锁定用户数据。
- 不得依赖外部构建服务或 CI 才能交付：任何克隆仓库的开发者都能在本机构建并运行。

## Development Workflow

- 每次变更后必须通过项目标准方式在本地完整构建并运行，走通
  “加载音频 → 播放 → 复读 → 记录进度”的最小使用路径作为冒烟验证。
- 变更不得要求用户迁移数据或重新配置；存储格式演进必须提供向后兼容的读取路径。
- 提交信息遵循 `type(scope): summary` 约定（如 `feat(player): ...`）。
- 复杂度必须有明确理由；违反本宪法的改动必须在变更说明中引用对应条款并给出理由。

## Governance

本宪法优先于所有其他开发实践。任何变更（功能、架构、技术栈）与本宪法冲突时，
必须先修订宪法：修改 `.specify/memory/constitution.md`，按语义化规则更新版本号
（MAJOR：原则删除或重新定义；MINOR：新增原则或章节；PATCH：措辞澄清与非语义修正），
并在文件顶部同步影响报告中说明修改内容。合规性审查在每次变更总结时进行：确认
无未解释的占位符、版本号与报告一致、日期为 ISO 格式（YYYY-MM-DD）。若运行时
开发指南与本宪法冲突，以本宪法为准。
